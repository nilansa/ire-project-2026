READ THIS FIRST

SciFact is not your submitted problem. It is a small scientific-claim retrieval dataset found in a separate local experiment. The original Microsoft-inspired MS MARCO / ANCE project remains the focus.

01 / IDENTIFY THE DATASET

What is SciFact—and why is it here?

SciFact stands for scientific fact verification, not science fiction. A query is a scientific claim; the retriever finds scientific abstracts that contain evidence supporting or refuting it.

A conceptual example, not a dataset quotation

Claim → scientific evidence

Claim: “A certain treatment reduces a specified biological marker.”

The retriever returns candidate article abstracts. Relevance judgments identify abstracts with evidence. A separate verification system could classify support versus refutation; retrieval alone does not verify the claim.

Original dataset: Wadden et al., EMNLP 2020. Read original paper ↗

Recovered artifact — provenance unconfirmed

Why it appeared in this project review

A local experiment dated September 2026 was discovered under ire-ann-learning-pilot-20260907/experiment/official_r8/. It used SciFact as a small testbed for comparing search backends with a teacher.

5,183 abstracts · 300 test queries · 50 candidates mined per training query · 100 final exact-search results evaluated.

The files establish that the run exists, not that you personally requested it. It is separate from the 50k MS MARCO experiment.

Do not mix experiments. Main documented study: MS MARCO / ANCE / top-200 / no teacher / one seed. Recovered side study: SciFact / MiniLM student and teacher / top-50 / two seeds. Comparing their absolute metric values is not meaningful because tasks, corpora, teachers and models differ.
02 / RESTORE THE ORIGINAL OBJECTIVE

What Microsoft Research actually asked

The 2026 challenge is about post-training retrieval models using high-quality feedback from reward models or humans—improving search and potentially downstream RAG. Your proposal selects the data-selection subproblem.

Microsoft question 1 · your current scope

Data selection

Which query–document pairs deserve expensive feedback, when we cannot label every possible pair?

Microsoft question 2

Loss formulation

How should pointwise, pairwise or listwise feedback be converted into a training objective?

Microsoft question 3

Computational efficiency

How can multiple teacher-scoring and post-training iterations be made affordable?

Top 10 / 100+

Re-encode full corpus and rank exactly. nDCG, MRR and relevance recall belong here.

The ANN system returns up to 200 candidates. The 200 is a shortlist depth; it is not necessarily the depth used to evaluate the final model.

The problem behind all five stages: At a fixed feedback cost, can a search-and-selection policy expose more valuable training supervision, yielding a better final retriever or improved RAG task outcome? Merely observing different example IDs is not a solution.

03 / INTERACTIVE METRICS LAB

Why retrieve 200 and measure the top 10?

Different cutoffs ask different questions. The final retriever may score an entire corpus; inspecting its first ten results measures top-rank quality. Inspecting its first 200 measures evidence coverage at a deeper cutoff.

First relevant rank
#25
May be later than the reporting cutoff.
ANN Recall@K (index quality)
|ApproxTopK ∩ ExactTopK| / K

Measures similarity to an exact-search shortlist. Not the fraction of relevant documents found.

Relevance Recall@K (evidence coverage)
# relevant documents among top K / # known relevant documents

Uses relevance judgments for a query, not the exact ANN reference list.

MRR@K (first-hit rank)
Across queries: average(1 / first relevant rank) if rank ≤ K, else 0

It ignores additional relevant documents once it finds the first one.

nDCG@K (rank quality)
DCG@K / IDCG@K
DCG@K = Σ relevance_gain(rank) / log₂(rank + 1)

IDCG is the best possible score based on all relevance labels for the query, including documents the model missed.

Recommended measurement hierarchy. First report corrected nDCG@10 (standard BEIR-facing ranking comparison), with Recall@10, @50, @100 and @200, MRR@10 where first-hit behavior matters, and MAP@100 for multiple relevant documents. For Microsoft's question, quality-versus-teacher-call curves are indispensable: equal scorer budget, identical final evaluation, and uncertainty across runs.

The cutoff is not a mathematical rule. If the actual user/agent consumes a top-5 or top-20 evidence context, also measure at that actual consumption depth. For a fixed 50k/5k corpus, comparing experiments requires using the same final evaluation corpus across methods.

SciFact / 5,183 documents

Original code normalized nDCG using sorted(labels), where labels contained only the retrieved top-100 documents. It should construct the ideal ranking from all judged relevant documents.

Concrete counterexample: Two relevant documents exist, but the retriever puts one at rank 1 and misses the other. Wrong ideal score: 1 → nDCG 1.000. Correct ideal score: 1 + 1/log₂3 → nDCG approximately 0.613.

Independent recomputation from all saved query rankings and official test qrels found the MRR@10 and relevance Recall@100 fields correct. nDCG was inflated for only 0–3 queries per condition because 277 of the 300 test queries have just one known relevant document.

The broad problem is real, but changing ANN methods and getting different selected documents is not by itself surprising. These selected papers are directly relevant and already occupy much of the nearby territory.

06 / WHAT TO DO BEFORE ANY LARGE TRAINING RUN

A small research plan with hard stop conditions

Make the source of the phenomenon identifiable, then establish useful teacher supervision, then study limited-budget gains.

Control rank sensitivity without any teacher or training

Take a fixed set of 200 identical passage IDs. Apply the selector after small rank permutations. If the selected-20 overlap falls near 43%, the original effect may be a selection-policy artifact rather than a distinctive ANN property. Compare stable top-20 and random/stratified controls.

Correct metrics and lock an evaluation protocol

Use the same untuned held-out query IDs and full corpus for every model. Implement BEIR-equivalent nDCG@10 and Recall@10/50/100/200 with a unit test where one relevant document is missing. Check query-text duplicates and qrel assumptions. Decide primary metric before seeing results.

Prove a teacher-feedback positive control works

Freeze exact top-200 and a strong, straightforward selection rule. Compare untuned student to teacher-distilled student using fixed calls and paired seeds. Investigate teacher miscalibration and false negatives if post-training still degrades. Stop backend claims until learning works.

Compare selected-pair budgets, not just ANN algorithms

At e.g. 5, 10, 20, 40 teacher-scored pairs per query, compare rank, random, ambiguity and diversity selection. Report final nDCG improvement, Recall and total teacher+search+training cost with uncertainty. Add ANN backends only after the selection baseline is healthy.

What would be a real mechanism?

Show that teacher-information gain, ambiguity, coverage or gradient diversity predicts improvement better than ANN recall, and that an acquisition rule exploiting this signal improves the budget–quality frontier consistently.

What would kill the proposal?

If rank perturbations explain the selected-pool disagreement, or no fixed-budget teacher baseline improves quality, treat backend comparisons as secondary. The stronger project may be a selection-policy stability study—or a documented negative result.
